# 灵音 · EchoBeats

**每一步都可核对的音频修复工作台。** 本地运行、离线处理、结果带数字。

[**下载最新版**](https://github.com/315-lvds/EchoBeats/releases/latest) · [许可证](LICENSE) · [第三方组件](THIRD-PARTY-NOTICES.md)

---

## 1. 这是什么

一个面向**已有音乐文件**的「检测 → 计划 → 处理 → 对照 → 留证」工作台。
它把音频修复当作**可测量的工程问题**，而不是"一键美化"：

| 一键增强类工具 | 灵音 · EchoBeats |
|---|---|
| 动完不告诉你动了什么 | **每一步报「做了什么 / 没做什么 / 为什么不做」** |
| 没有量化前后对照 | **前后对照表**，并区分**改善判据**与**设定目标** |
| 不报"这一步没修到东西" | 修复效果评估会写明：**改动量 ≈ 0 = 那一步基本没动** |
| 没有"做不到"的清单 | 做不到的**逐条登记原因** |

**它不是什么**

- ⛔ 不是"AI 一键变好听"。**不承诺**音频被改变或变好，只承诺**过程可查**。
- ⛔ 不替代 iZotope RX / Cedar 这类专业修复工具（它们是这一行的标杆，本软件不声称超越）。
- ⛔ 不上传你的音频：全部处理在本机完成。
- ⛔ **不产出总分**。"这首歌值几分"这类东西刻意不做 —— 只给多维度的独立证据。
- ⚠️ 编码修复（MP3/AAC 损伤）· 音频超分 · 计算混音重塑**在计划内、分期推进**：
  它们各自的前置检测器尚未建成，所以现在不接线（⛔ 没有触发条件的动作"装了也白装"）。

## 2. 现在能做到什么（都带实测数字）

### 2.1 单曲处理链

| 能力 | 实现 | 实测 |
|---|---|---|
| **去削波** | 凸优化（加权 ℓ1 + Douglas–Rachford），**非**模型生成 | 对真值 ΔSDR：θ_c=0.20/0.50/0.80 ⇒ **+0.86 / +2.36 / +1.96 dB** |
| 去削波（快路线） | Chambolle–Pock，快约 30× | 同上三档 ⇒ **+0.54 / +1.39 / +2.26 dB**（深削波上反超 ℓ1） |
| 去削波（局部化） | 只重建**削波所在的那一小段**，其余逐样本原样 | 稀疏削波曲 **6.8×**（32.8 s → 4.8 s），**Ω 外逐样本差 0.0** ⇒ 窗口间无需交叉淡化 |
| **动态还原** | De-limiter（外部权重，强制 44.1 kHz） | 用户 A/B 盲听：动态 **3.68 → 5.09** |
| **响度归一** | 增益 ＋ 真峰值限幅，三档交付目标 | 落点 −14.00 LUFS 精确；见 §3.2 的"它会不会破坏前面的修复"（实测：不破坏） |
| **残差运输** | 把高采样率源的超声内容搬回输出 | 96 kHz 源实测：引擎自报 `ultra_22k_rel_db` 源与输出**逐字一致** |
| 收尾三件 | 去直流 · 真峰值 · 抖动 | 去直流：DC 0.5 → 1.2e-12 而 **1 kHz 变化 0.00 dB** |

### 2.2 诊断

七层：**特征提取 → 损伤检测 → 可闻性（掩蔽阈）→ 纹理（谱峰度）→ 感知描述子 → 分离质量 → 来源与对比校验**。

处理动作与诊断的对应关系**写成了代码**（动作注册表）：每条动作带**依赖判据 / 门禁 / 真值 / 现状 / 依据**，
`plan()` 把"诊断 → 计划"连同**未执行及原因**一并给出。**当前 15 条动作：可用 9 条**，
其余 6 条逐条登记原因（如编码修复缺"检测器 E"）。

### 2.3 批量

成品**每首跑完立刻归位**；断点续传按**稳定批次 id** 生效（同批重跑实测 `done=0 · skipped=6`，真跳过）。

### 2.4 音乐库

用户库与成品库两面；两面都可排序（标题 / 艺术家 / 专辑 / 时长）；成品库另可**按名字或工序筛选**，
并显示**这一首走过哪些工序**（工序读自批次记录，⛔ 不依赖写入你文件的私有元数据）。

## 3. 实测数据

### 3.1 修复到底有没有发生（对一首真实曲目的逐环节实测）

| 环节 | 与上一环节相比 |
|---|---|
| 原曲 → `01 去削波` | SDR **+93.17 dB**（≈ 未改动：该曲 22 kHz 以上只有 0.016% 能量、削波检出 0 ⇒ **没有可修的**） |
| → `02 动态还原` | SDR **−1.24 dB**（**改动显著**） |
| → `03 响度归一` | SDR **+12.67 dB**（改动小） |
| 成品 vs 原曲 | 峰值 1.000000 → 0.761344 · **SDR +4.49 dB** ⇒ **确实被大改过，不是复制** |

### 3.2 响度归一会不会破坏前面的修复（跨 63 对前后对照）

测的是**电平不变量**（跨响度可比）：DR · PLR · CF · PSR · LRA · 削波样本。

| 指标 | 归一前后的差 |
|---|---|
| DR / CF / LRA | **0.000** |
| PLR / PSR | 最大 **0.010** |
| 削波样本 | **0 → 0**（没有新增削波） |
| 跨曲目 DR 极差 | **4.70 → 4.70**（各曲的动态差别**完全保留**） |

⇒ **结论**：归一实质是**一次增益**（＋极小的真峰值限幅）⇒ **不破坏**前序修复，
**也不会把各曲变成一个样子**（它对齐的是响度，不是动态）。
⚠️ 如实说明：以上是**电平不变量**的结论；"更好听"需要**听测**，本版本尚未做（见 §5）。

## 4. 安装与使用

### 安装

1. 打开 [**Releases**](https://github.com/315-lvds/EchoBeats/releases/latest)，下载 `EchoBeats-Setup-<版本>.exe`（约 340 MB）。
2. 双击安装。默认装到 `%LOCALAPPDATA%\Programs\EchoBeats`（**用户级，不需要管理员**）。
3. ⚠️ 向导会**记住上一次的安装路径**；若默认填的不是上面那个目录，请手动改回。
4. 首次启动先选「用户音乐目录」「灵音库」位置与库模式，然后才扫库。

**关于安全提示**：本软件**没有购买商业代码签名**，Windows SmartScreen 会提示"未知发布者"。
- ⛔ 本软件**不提供自签名证书**，也⛔ **不建议**把任何证书导入"受信任的根证书颁发机构"
  （那是恶意软件的常见做法）。
- 请用 Releases 里公布的 **SHA256** 校验文件完整性。

**支持格式**：FLAC / MP3 / OGG / Opus / WAV / AIFF。
⚠️ ⛔ 不支持 `m4a` / `aac` / `wma` / `mp4` —— 原因见 §6（为把 GPL 与编解码专利池移出分发物）。

### 典型用法

1. **音乐库** → 「选择音乐目录（扫描导入）」把音乐读进来；
2. **库操作**（同一页）→ ① 建立索引 → ② 对账（四态）→ ③ 同步（按库模式）→ ④（可选）写私有元数据；
   每一步都写着"做什么、会不会改文件"；
3. **工作台** → 选中一首 → 勾选模块 → 「开始处理」；
4. **批量** → 选多首（带封面的列表）→ 运行；成品**每首立刻归位**；
5. **生成报告** → 按钮展开：整曲报告／（有成品时）原曲报告 · 处理后报告 · **对比报告**
   （原曲面板 ＋ 处理后面板 ＋ **差异面板**：波形相减 · 频谱相减，绿＝多了 · 红＝少了）。

### 卸载

控制面板卸载即可；**默认保留你的数据**（`%LOCALAPPDATA%\EchoBeats\data`）。

## 5. 已知边界（写在明面上）

| # | 项 | 说明 |
|---|---|---|
| 1 | **没有听测** | 所有结论是**实测数字与模型估计**，⛔ 不等于听测结论 |
| 2 | 编码修复 / 超分 / 混音重塑 | **分期推进**，前置检测器未建成 ⇒ 暂未接线 |
| 3 | 应用侧单实例 | 同一数据目录开两个窗口会互相抢引擎 |
| 4 | 真峰值口径 | 报告里 `true_peak_dbtp` 沿用**样本峰值**口径，已在界面标注 |
| 5 | 部分诊断量 | 少数指标仍是"已声明未测"状态，界面如实标注，⛔ 不填 0 充数 |
| 6 | 源码 | **暂未公开**（本仓库当前只发布安装包） |

**被实测证伪、因此不采用的想法**（主动登记）：神经算子"零样本换分辨率" ·
生成式带宽扩展当作"还原"（违反感知-失真定理）· 辛/保结构网络 · r-适配 ·
以及本项目的两条**自我订正**：曾估算"去削波一首要几十分钟"（实测为 **13–87 秒**，已订正）；
曾以为"分块独立求解能显著加速"（实测 **0.90×，无收益**，⛔ 未采用）。
