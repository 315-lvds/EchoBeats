# 灵音 · EchoBeats

> **每一步都可核对的音频修复工作台。**
>
> 先把音乐读进来做诊断，再对单曲或整批做模块化处理；**每一步都告诉你动了什么、
> 数值前后差多少、以及哪一步没修到东西**。

本仓库当前**只发布安装包**（见右侧 **Releases**）。源码暂未公开。

---

## 一、它是什么

一个**本地、离线**的音频「检测 → 计划 → 处理 → 对照 → 留证」工作台，面向
**已有的音乐文件**（不是录音棚里的多轨工程）。

它和"一键增强"类工具的区别只有一条，但这条很硬：

| 一键增强类工具 | 本软件 |
|---|---|
| 动完不告诉你怎么动的 | **每一步报「做了什么 / 没做什么 / 为什么不做」** |
| 不给量化前后对照 | **前后对照表**，并区分**改善判据**与**设定目标** |
| 不报"这一步没修到东西" | 修复效果评估会明确写：**改动量≈0 = 那一步基本没动** |
| 没有"做不到"的清单 | 做不到的**逐条登记**，并说明为什么 |

## 二、它不是什么

- ⛔ **不是**"AI 一键变好听"。本软件**不承诺**音频被改变或变好，
  只承诺「**经过了链路、做了什么、没做什么及原因**」都有据可查。
- ⛔ **不是**母带软件（不替代 iZotope RX / Cedar 这类专业工具的完整能力）。
- ⛔ **不是**在线服务：全部处理在本机完成，不上传你的音频。
- ⛔ **不产出总分**。"这首歌值几分"这类东西本软件刻意不做 ——
  它只给**多维度的独立证据**，不做凌驾于测量之上的权威。
- ⚠️ **编码修复（MP3/AAC 损伤）· 音频超分 · 计算混音重塑都在计划内，分期推进**。
  它们各自的前置条件尚未建成（编码损伤 / 有效带宽 / 声场结构的检测器），所以**现在不接线** ——
  ⛔ 没有触发条件的动作"装了也白装"。⇒ 登记在案，⛔ 不假装可用（这也是它们暂未出现的原因）。

## 三、现在能做到什么（都带实测数字）

| 能力 | 说明 | 实测 |
|---|---|---|
| **去削波** | 硬削波平顶修复（凸优化，**非**模型生成） | 三条路线对真值 ΔSDR：加权 ℓ1 `+0.86/+2.36/+1.96` · Chambolle–Pock `+0.54/+1.39/+2.26`（按削波深度分三档） |
| 去削波 · 局部化 | 只重建**削波所在的那一小段**，其余逐样本原样 | 稀疏削波曲 **6.8×**（32.8 s → 4.8 s）；**Ω 外逐样本差 0.0**（所以窗口之间不需要交叉淡化） |
| **响度** | 三档交付响度 ＋ 真峰值安全 | 落点 −14.00 LUFS 精确；真峰值不越限 |
| **动态还原** | De-limiter（外部权重） | 用户 A/B 盲听：动态 3.68 → 5.09 |
| **诊断** | 特征 / 损伤 / 可闻性（掩蔽阈）/ 纹理 / 感知 / 来源检查 七层 | 见下方「已证伪的想法」 |
| **批量** | 整库成批处理，**成品每首跑完即刻归位** | 断点续传：同批重跑 `done=0 · skipped=6`（真跳过） |
| **音乐库** | 用户库 / 灵音库两面；排序：标题 / 艺术家 / 专辑 / 时长 | — |

**修复效果评估**（掩蔽阈模型）给出的不是"好坏分"，而是两个正交量：
**改动量**（做了多少）与 **可听改动占比**（后果多重）。
⚠️ 两个必须并看 —— 单看一个会误判（改动量≈0 也可能意味着那一步根本没动）。

## 四、安装

1. 打开本仓库的 **Releases**，下载最新 `EchoBeats-Setup-<版本>.exe`（约 340 MB）。
2. 双击安装。默认装到 `%LOCALAPPDATA%\Programs\EchoBeats`（**用户级，不需要管理员**）。
3. ⚠️ 安装向导会**记住上一次的安装路径**：如果它默认填的不是上面那个目录，请手动改回来。
4. 首次启动会先让你选「用户音乐目录」「灵音库」的位置与库模式，然后才扫库。

**关于安全提示**：本安装包**没有购买商业代码签名**，因此 Windows SmartScreen 会提示
"未知发布者"。
- 这是**没有证书**的正常表现，⛔ 本软件**不提供**自签名证书，也⛔ **不建议**你把任何
  证书导入"受信任的根证书颁发机构"（那正是恶意软件的做法）。
- 下载时请用 Releases 页面上公布的 **SHA256** 校验（`安装说明.md` 里也有），
  确认拿到的是同一份文件。

**卸载**：控制面板卸即可；卸载**默认保留**你的数据（`%LOCALAPPDATA%\EchoBeats\data`）。

**支持的格式**：FLAC / MP3 / OGG / Opus / WAV / AIFF。
⚠️ ⛔ 不支持 `m4a` / `aac` / `wma` / `mp4` —— 原因见下方许可一节（编解码相关的专利与许可问题）。

## 五、它怎么被验证（这是最重要的部分）

一份**主动登记自己错在哪**的清单 —— 与本项目"不设总分、只给证据"的做法一致：

**已被实测证伪 / 因此不采用的想法**

| # | 想法 | 结论 |
|---|---|---|
| N1 | 神经算子"零样本换分辨率" | 实测证伪：换分辨率即混叠，唯一解是多分辨率训练 |
| N2 | **生成式带宽扩展当作"还原"** | 违反感知-失真定理：生成的高频不可能同时"好听"与"正确" |
| N3 | 辛/保结构网络 | 无哈密顿演化，不适用 |
| N4 | r-适配 | 违反"不改内容"红线 |
| N6/N7/N8 | Parareal/MGRIT 原版迭代 · POD/DMD 承载瞬态 | 不搬用 |

**被实测推翻的自家判断（也在案）**

- ⚠️ 曾把"一首去削波要几十分钟"写进文档 —— **那是估算，不是测量**。
  按真实曲目各自采样率实测外推：192 kHz、3–6 分钟的歌约 **13–87 秒**。**已订正。**
- ⚠️ 曾以为"分块独立求解"能显著加速 —— 实测 **0.90×（无收益）**，
  质量无损（对真值 ΔSDR **0.000**）。原因是早停已把迭代压到约 10 轮，
  瓶颈是"每轮 ∝ 全曲长度"。⇒ **未采用**。

**边界写得比能力多**，是因为本项目认为：一个工具**说自己做不到什么**，
比它说自己能做什么更能建立信任。
